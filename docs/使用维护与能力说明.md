# 使用、维护与实际能力

核对日期：2026-10-09。本文说明当前实现，不代表新功能实施方案。

## 使用入口
先将本地 robot-test-knowledge 目录添加或打开为 Codex 项目，再开启该目录内的会话。当前聊天根目录在知识库父目录，不能假定它自动发现下级 .agents/skills。其他三个项目也未安装共享技能。
官方说明：仓库技能从当前目录向上至仓库根的 .agents/skills 发现；技能是可复用指令及资源，https://learn.chatgpt.com/docs/build-skills 。在界面技能选择器确认两项技能可见；不可见时明确提供 SKILL.md 路径读取，或重新打开项目。

在本库试用时明确要求只读访问 elephant-pytest，不把输出直接写到原项目。提供产品、接口、当前文档/SDK 版本、工作簿与 Sheet。知识库保存的路径与快照依赖本机，其他电脑应重新定位项目与核对来源。

用例审查提示词：
使用 testcase-iteration 技能，审查 elephant-pytest/mycobot_450 的 get_debug_state。先读取目标现有规则、技能、Excel Sheet、测试文件及可信接口资料；输出已有测试点、证据缺口和逐项变更建议。原文件只读，不连接机器人。涉及新方案先提出三个问题，等待确认执行。

生成提示词：
使用 pytest-generation 技能，依据已确认用例与当前项目规则生成单接口测试副本。保留 Excel 字段、fixture、参数化 ID、Allure、marker、skip、日志和恢复逻辑。仅做 AST 静态检查，报告未核实的 SDK 契约，不导入或执行硬件模块。

两技能为指令工作流，需要 Codex 读取资料和实施；不是一条命令自动生成测试的脚本。完整链路为来源核对 → 用例审查 → 用户确认 → 测试副本 → 差异/静态验证 → 经审查后合入项目。硬件执行单独授权，本库不实现该步骤。

## 当前能力与证据
已实现并验证：文件结构/脚本语法/技能副本一致性/引用存在检查；来源文件 SHA256 比较；固定 Git 提交导出两个技能；默认预览、同名拒绝覆盖、lock 记录；6 项隔离同步测试。
上次 61 项检查 = 20 项本库检查 + 41 个来源文件哈希比较，不是 61 条业务测试。来源哈希只判断是否变化，不证明接口契约正确。
两技能已通过 manifest 校验，且一次人工驱动静态试用生成 get_debug_state 演示副本，只修正 Allure 标签，未生成新的接口测试或修改 Excel。没有真实技能自动触发端到端测试记录。
可以支持但尚未全面验收：基于充分资料补测试点、生成 pytest、编辑 Excel 副本、审查断言与恢复。这些由 Codex 工作流实施，不是已提供的独立生成程序。
只有规划：defect-analysis、coverage-review、test-report，尚无对应 SKILL.md 或运行实现。
尚未实现：自动知识检索服务、完整 SDK 知识库、定时同步、GitHub CI、自动升级/回滚脚本、跨项目自动加载、真实硬件执行/Allure 报告生成。原项目 docs/knowledge 接入尚未实施。

## 维护职责
公共 standards 保存跨项目约束；fundamentals 保存测试设计依据；接口签名、fixture、运动常量等留在原项目，projects 维护差异索引和来源快照。目标项目新规则优先核对，不能直接套用旧快照。
技能修改维护 skills/，同步同名 .agents/skills 副本；references/project-context.md 在两技能包中各有一份，项目差异变化应同步修改四个对应副本。校验会检查每项技能源与发现副本一致，但不会自动检查两个技能之间的参考内容是否一致。
每次任务更新唯一交接文档；规则变化更新 AGENTS；技能变化更新技能；发布记录写 CHANGELOG。新方案按用户确认流程维护方案总文档。

## 离线验证与版本同步
从知识库根执行：
```powershell
python scripts/validate_offline.py
python scripts/test_sync.py
python scripts/validate_offline.py --sources
```
前两项用于本库；第三项依赖 source-manifest.json 内本机路径。原项目正常变更会触发 source drift，应重新审查并更新快照，不能机械替换哈希来消除报错。现在没有快照刷新脚本。
技能官方验证使用 skill-creator/quick_validate.py，Windows 使用 Python -X utf8；此工具属于本机技能环境，不是仓库内依赖。

审查差异、校验通过后提交并推送 Git；新版本使用新标签，不移动 v0.1.0。项目安装固定完整 40 位提交，首次安装先预览，再显式 --apply；本轮范围仍为仅本库验证，不实际安装到三项目。
升级/回滚目前需要人工在 Git 分支审查并操作，脚本遇到既有 lock 或同名技能会拒绝。它不下载远程、不自动升级，也不会安装 standards 或 templates；需要公共规范时显式读取知识库文件。
不要上传密钥、连接配置、原始工作簿和硬件日志。
