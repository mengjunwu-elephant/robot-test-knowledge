# 技能包迭代维护

现状：用户已确认安装成功，当前会话实际发现 robot-test-knowledge 的 testcase-iteration 与 pytest-generation，两项版本为0.2.0。

## 使用者操作
1. 在正常任务中记录问题：当前项目/接口、发给技能的原话、实际结果、期望结果。附最小例子，不发送密钥与设备连接信息。
2. 在知识库聊天提出修改请求。先检查目标项目现有规则，区分公共技能问题和项目专属契约；新方案遵循至少三个收敛问题及确认执行要求。
3. 维护者提交修正版、验证记录、新版本包。使用者无需手工编辑SKILL.md。
4. 下载新版本安装入口，关闭旧任务后运行；重启应用、刷新个人插件来源，更新或重新安装，再新建聊天确认新版本与行为。
5. 保留旧版本包。新版本有问题时重新登记旧版本并刷新/重新安装，原项目文件不受技能包版本切换影响。

## 维护者操作
唯一维护源是仓库skills/，不要直接改个人plugins/cache中的安装副本，避免缓存更新丢失。
规则、技能指令与知识资料分开：公共约束更新AGENTS/standards；工作流更新对应SKILL.md；各项目API、返回值、fixture与SDK版本由原项目记录，公共包references只维护已核对的差异摘要。
修改后同步.agents/skills副本和各技能references。用用户提供的同一任务做前后行为验证，确认修正点和原有约束仍成立。
静态与隔离校验：validate_offline.py、test_package.py；安装入口改动另运行test_launcher_windows.py，使用临时user-root，不写真实用户插件目录。
小范围修正可发布0.2.1；新增能力可发布0.3.0。不复用0.2.0承载不同内容，因为安装器拒绝覆盖已变动的同版本。
当前plugin.json版本被build_package.py读取；但workflow发布标签、test_package.py断言与Windows启动器文件名仍写死0.2.0。发布下一版必须一并修改，现阶段不能只改plugin.json就声称完成自动升级。
确认验证结果后更新CHANGELOG、唯一交接文档与涉及的方案总文档；提交Git并发布新包。

## 更新边界
GitHub源文件更新不会自动替换已安装插件。安装器登记个人来源，不自动点击应用安装/启用按钮。支持本地来源的桌面客户端刷新/安装后才使用新的缓存副本。
安装器保留旧版本目录，更新个人来源路径；遇到同名外部插件或已修改的同版本文件会停止。
官方本地插件维护说明：https://developers.openai.com/plugins/build/plugins

## 当前0.3.0机制
版本从plugin.json读取，发布标签与安装测试已取消0.2.0固定值；Windows自解压启动器仍需随版更新。main推送只校验，维护者手动运行发布。更新入口见团队使用步骤；匿名API可能限流，失败改用Release手动下载。
