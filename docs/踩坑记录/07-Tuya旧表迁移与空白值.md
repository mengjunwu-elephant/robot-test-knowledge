# PIT-007 Tuya 旧表迁移与空白值

## 可见表现与证据边界

2026-10-26 审查用户提供的“修改 Tuya 测试用例”对话。首次迁移报告 265 条接口记录；用户指出少行后，执行者补回旧表第 53、260–268 行，报告总数 275。之后用户指出旧表合并步骤适用于覆盖的每条用例，执行者查出 G259:G268 与 I259:I268 等合并范围，并撤销续行的“待补充”误判。用户还指出灰色填充不完整及空白区出现 `0`；执行者报告按整行修正灰色、清除 81 个真实保存的文本零。

这些事实来自对话中的用户反馈、工具输出和执行者复查描述。本次未独立读取仓库外 Tuya 工作簿，也未验证最终文件在 Excel/WPS 中的视觉状态。对话显示迁移与交付检查曾漏项，不据此断言最终交付仍有错误。

## 可复用做法

- 迁移前建立旧 Sheet、行号、编号与新行的全量映射；读取合并锚点及覆盖范围，再判断续行是否真正缺内容。不能按步骤/预期非空筛除用例。
- 共享步骤或预期仅在原表语义和当前批准范围均支持时迁移；编号和执行结果独立。颜色覆盖与模板基线冲突时，列出区域、颜色和含义，询问是否沿用；不自动推广 Tuya 的灰色方案。
- 保存后重新读取最终文件，对照源表及模板查合并、空白、异常占位值和受影响区域的实际显示。`0` 可能是合法业务值，须按单元格及字段含义判断。

适用：旧用例跨模板迁移。文件占用时是否覆盖或另存由当前项目和用户要求决定，不纳入本记录的通用规则。任务短参考见技能 [PIT-007](../../skills/testcase-iteration/references/pitfalls/tuya-workbook-migration-pit007.md)。
