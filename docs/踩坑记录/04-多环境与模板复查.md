# PIT-004 多环境行为、模板保真与最终复查

## 场景与证据级别

[PR #2](https://github.com/mengjunwu-elephant/robot-test-knowledge/pull/2)的提交说明将 Pro450 用例编写过程概述为三个问题：纯仿真预期混入真机动作、首页与项目模板不一致、多轮修订后只记录部分静态复核。当前仓库没有原对话、原始需求、模板或最终工作簿，因此这些具体事件及其修复结果**未独立核验**；不能把该概述写成真实项目验收结论，也不能据此规定所有项目的仿真模式或首页内容。

从已有团队规则可以独立推出可复用的流程底线：预期必须有需求或用户确认的依据；保留批准模板与原字段；审查范围以最终交付文件为准。PIT-004 只把这三项落到多环境测试点、模板 Sheet 和末版复查，不新增 SDK 或机器人行为规则。

## 正确做法

编写任务先确认 Sheet 范围和测试点。每个环境分别写清操作对象、观察对象、预期动作、禁止副作用与通过条件；某环境是否让实体设备动作只能引用该项目可信资料或用户确认。只读审查已获授权时直接检查，不进入编写的确认关口。

新表复制已批准模板，保留首页、环境登记区、字段顺序和历史执行结果；是否增减 Sheet 或结果列按已确认范围处理。交付前针对**最终文件**核对结构、格式、内容与视觉。最后一次改 Sheet、合并区、样式或内容后，重查受影响部分，并如实说明没有覆盖的部分。

## 受控流程演练（虚构资料）

以下契约专为检查流程而设，不描述 Pro450 或任何真实设备。假设一份已批准的虚构协议规定：`SIM` 命令只改变模型状态，实体状态保持不变；`LINKED` 命令同时改变模型与实体状态。批准模板已有“首页”“环境登记”“用例”三个 Sheet，分别记录环境结果，不允许删页。演练只读文档，不生成工作簿、不调用 SDK 或实体设备。

1. 对“状态切换”测试点，`SIM` 行写模型为操作及观察对象，预期模型变化、实体不变；`LINKED` 行写模型和实体均变化。两行均引用**这份虚构协议**，不把行为推广给真实项目。
2. 编写流程在生成前评审上述测试点和环境判据；如果只有“仿真/联动”标签、没有协议，实体是否动作应列为待确认。已授权的只读审查直接检查现有文件，不要求重新批准测试点。
3. 模板检查需保留三个 Sheet、字段与环境登记区；删掉“首页”的假想修改应判为不符合批准模板。若末次调整了合并区，前一次静态检查不能代表最终版，必须重跑受影响的结构与格式检查，并复看该区域。

结果：规则文字能区分编写与只读审查，并能指出缺契约、擅改模板和末版未复核三类问题。这是维护者的桌面流程演练，**不是独立模型盲测、Excel 工具回归或真实项目验收**。

## 适用范围、版本与未决项

适用于有多环境行为差异、批准模板或多轮修改的用例任务；不要求每个项目都有仿真、真机联动或相同 Sheet。技能短参考为 `skills/testcase-iteration/references/pitfalls/environment-template-review.md`。流程修订已随 v0.8.2 正式包分发（2026-10-14）；发布记录见[唯一交接](../项目交接文档.md)。这是发布状态，具体客户端是否已加载仍需单独确认；原 Pro450 资料未独立核验的限制保持。

待补证据：若需把 Pro450 具体事件标为已核实，应取得可共享的脱敏原对话、需求/模板与最终文件检查记录，逐项复核后更新本记录。缺这些资料不妨碍采用上述已由公共规则支持的流程底线。
