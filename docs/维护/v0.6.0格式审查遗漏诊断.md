# v0.6.0格式审查遗漏诊断

日期：2026-10-10。依据：用户提供同事对话截图及v0.6.0技能、参考、脚本。未取得同事完整会话、工作簿和实际检查报告，因此不能确认其是否真正采用了夹爪配方或执行过任何工具。截图内助手自述不是工具执行证据。

## 发现

1. SKILL设计与交付段明确：采用夹爪基线的已确认Sheet再运行review_format.py。AGENTS和workbook-review也要求该条件下另做格式检查。如果截图所述采用基线属实，遗漏是未落实现有要求，不是技能包没有格式能力。
2. cell-format将格式标准适用条件写成“适用Sheet和是否使用此基线须在范围确认中明确”。但技能没有一个清楚的审查任务交付清单，容易把条件限定读成整项格式审查可选。识别为夹爪不等于已确认采用其配方；识别需依据字段及用户标准而非名称。
3. review_format.py的PROFILE固定为gripper-v1.4.1-format.json；mapping仅支持Sheet名到基线Sheet。它不是通用格式校验器。不能修正为所有项目无条件运行并强套夹爪标准。
4. review_workbook.py只管结构和填写规则，不替代字体/边框检查；视觉抽样也不能证明全域格式一致。需要分别报告静态格式、视觉及内容完成状态，未完成不能称完整技能审查。
5. confirmation-flow已说明三个关口适用于编写/迭代；截图要求再次确认后补做同范围只读审查，属于不必要的重复确认。既有审查授权可继续完成遗漏；未知标准或新增写入才需要收敛。
6. 当前52项离线完整性和样式工具回归没有证明模型在“审查”请求下会选择完整检查。工具正确不代表工作流触发正确。

## 待收敛的优化方向（非已批准实施方案）

区分审查与编写路由；为完整审查明确结构、格式、内容、视觉四项及各自范围与完成状态。用户可明确缩小范围。已有格式标准则按其检查；标准缺失先记录实际样式及依据缺口，不自动套夹爪。适用时必须运行已有格式工具，无法适用时说明原因并采用基于批准标准的只读检查或明确报告尚未验证。缺少渲染能力不能冒称视觉完成。

交付保留工作簿版本/哈希、Sheet范围、标准来源、实际使用方法及报告、未检查项。只有适用项完成才称完整审查；完成含发现不合格，不等于全部通过。截图反馈应使用相同任务离线验证，另用非夹爪模板验证不强套、仅内容审查验证不越界。

已提出三个问题：默认审查范围、非夹爪标准处理、实施深度。待回答及“确认执行”后形成P0/P1/P2正式方案。本轮只诊断，未改技能或脚本、未发布新版、未修改同事Excel或运行测试。
