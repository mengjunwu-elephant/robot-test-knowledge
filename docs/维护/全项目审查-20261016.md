## 发现

### AUD-01 / P2：进行中流程缺少接口返回语义前提

位置：`skills/pytest-generation/references/in-progress-and-stall.md:29–31`，对应镜像及生成复核说明同受影响。此项为此前 PR 审查发现，本次确认仍未处理。

通用规则强制进入状态接口返回后立即测试，且禁止中间等待。如果该接口完成校准/回零后才返回，测试会在动作结束后执行；如果返回仅表示受理、设备稍后才进入状态，测试又可能过早执行。两者都无法保证验证“进行中”。应先核验项目批准的返回语义和状态确认方式；契约不明时待确认，不能统一挪动原步骤的等待。没有证据证明 Marsdog 的具体接口一定属于上述情况。

### AUD-02 / P2：默认模板模式漏检空表头下的额外正文列

位置：`skills/testcase-iteration/scripts/review_workbook.py:147–149`，镜像同样受影响。

实际列覆盖检查仅在 custom layout 分支执行。默认模板模式只检查额外表头；新增列的表头为空、正文有内容时，不会报告未映射。

复现：以通用软件模板和现有回归的有效案例构造临时 XLSX，在模板 A—P 之外写入 `Q3=unmapped business data`，Q1/Q2 保持空白。调用正式 review 入口，结果为 `static_checks_passed=true`、`unresolved=false`、`scope_complete=true`、`issues=[]`，但 Q 列内容未被结构检查覆盖。临时文件与原模板隔离，原模板未修改。

应将实际列覆盖核对用于默认模板和显式布局两种模式；未映射正文列必须报告，不能声称完整静态覆盖。此为结构工具边界，现有格式工具能报告此类额外列，不应将两个结果混为一谈。

### AUD-03 / P2：两个独立编号列共用查重集合，合法值被误报

位置：`skills/testcase-iteration/scripts/review_workbook.py:155–168`，镜像同样受影响。

工具支持批准布局同时包含“用例编号”和“指令序号”，却将两个字段的值存入同一个 seen 字典。合法的一行 `用例编号=1、指令序号=1` 会在 B2 报 DUPLICATE_ID，即使两列各自均无重复。跨行不同字段的同值也会互相干扰。

复现使用批准四列布局（用例编号、指令序号、测试步骤、预期结果），必需语义和表头均齐全；仅两种编号取值相同，就得到上述错误。应按批准的身份字段分别查重，同时保留同列合并锚点继承；如项目要求跨列全局唯一，应由明确契约决定。

### AUD-04 / P3：Windows 较长用户根路径下，安装暂存路径超限

位置：`packaging/install.py:75–81`。

在本机 Python 3.10.5 / Windows 环境，临时用户根较长时，版本父目录、暂存目录和技能相对路径叠加后超过系统支持长度。独立于沙箱限制的复测中，预计最长暂存路径 297 字符，实际报 `FileNotFoundError / WinError 206`，marketplace 未创建。常规临时用户根下安装及 CMD 成功/失败路径均通过。

影响限于未具备相应长路径支持且目标根较长的环境，不是所有 Windows 安装都会失败；未发现已有版本被覆盖。可增加写入前路径长度预检和明确诊断，或在受支持环境采用长路径处理。不能仅靠反复重试解决固定路径超限。
