# 公共规则现状核对

2026-10-10。只读盘点结论，未实施新规则重构。

## 当前内容

standards/team-rules.md是公共测试规则源，随两项技能references/team-rules.md分发，并同步.agents镜像。内容包含任务授权边界、测试点评审、写作确认流程、格式标准、资料与冲突处理、结构保护、设备限制、方案交接、团队审核发布、共享资料、可操作写法及四项审查交付。

standards/testing-contract.md包含单接口调用、结构/业务断言、回读恢复、异常及超时的自动化约束。fundamentals/evidence-first.md包含证据和设计原则。standards/git-sync.md包含固定提交同步与回滚。根AGENTS.md同时保存测试工作规则和本仓库维护/发布规则。templates/项目接入-AGENTS片段.md负责让目标项目读取安装包规则，不应整文件替换原AGENTS。

## 应优化的原因

- 内容有用，但公共底线、具体用例流程、仓库维护和历史记录混杂；两项技能都加载用例Sheet与样式细节，路由不够清楚。
- 先读资料、保护结构、授权边界等在AGENTS、team-rules、testing-contract重复，容易只改一处；镜像复制有用途，重复写同一条规则无额外收益。
- 至少三个问题、确认执行与方案交接属于用户过程要求；应明确哪些任务需要新方案、哪些是已授权只读审查，不能造成反复确认。
- team-rules称禁止collection，AGENTS存在“无副作用审查后另有授权”的例外；规则必须按任务/授权条件统一表达，不能自行扩大硬件权限。
- 新通用格式与四项审查已在仓库源，但标题仍0.6.0；同事正式0.6.0不含这些修订，源码/正式版状态应明确区分。
- AGENTS含“本轮已确认方案A”、0.4.0打包等历史句子，应移出当前约束，避免历史授权被当作新任务许可。
- 固定提交导出、正式Release更新、Cursor分支刷新是不同机制，不能用一句固定版本表述覆盖全部渠道。

## 收敛问题与边界

已询问公共规则/技能细则拆分、确认流程适用范围、维护与使用规则分离。推荐简化公共入口，保留证据、授权、保护、冲突和诚实交付底线；专门流程放回技能；维护发布留本仓库。待用户选择及授权后另行实施。不得擅自删除用户确认流程、运动限制或项目差异。
