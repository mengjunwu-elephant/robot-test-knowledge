# 夹爪v1.4.1用例完善实施方案

日期：2026-10-10。阶段：已按用户六项纠正生成266条修订副本。以下实施方式以本次修订为准，441条初稿退回。

## 目标和已确认范围

将已认可的接口测试点落实为可以逐项判断的测试用例：每条写清输入、前置状态、操作、观察结果及恢复责任；没有可靠依据的预期明确留待确认，不写猜测值或通过结论。

用户已确认展示方式和全部测试点内容，缺少协议、阈值等依据的部分保留待确认，无调整；随后回复“确认执行”，授权本次输出完整方案。原范围为六个用例Sheet全部完善，首页只核对。依据为[已认可的接口测试点评审](试用评审/夹爪v1.4.1-测试点评审.md)和[原记录索引](试用评审/夹爪v1.4.1-测试点索引.json)。不再次询问已确认内容。

本方案只涉及用例编写。SDK源码可作为版本明确的接口实现证据，不作为固件需求替代；pytest生成、源码审查、自检、收集及执行均不在范围内。当前不连接设备。

## P0：先把用例内容写清楚

### 保护原件和来源

从现有 `Pro力控夹爪-固件-v1.4.1-测试用例-20261009.xlsx` 创建独立副本，不从v1.4.0迁移。开始生成前核对原件SHA256应为 `47c8032f2881a90fe4c52c6e0960460756c1aee973488350c2cc7792c5eadaed`；若变动，先检查差异再决定采用哪份，不用旧快照覆盖。

保留原Sheet名称及顺序、字段及顺序、环境分列、公式、原编号、已有执行记录和证据。首页内容和布局保持原样，只在独立缺口清单中记录核对结果；不自动填写现场信息。

### 测试点落实方式

- 按接口名称归组，设置接口和读取接口分别写清目的；串口和Modbus分别保留，不合并执行结论。
- 正常、边界、库异常、设备异常、状态变化及断电保持各有独立判定。库调用前抛出异常不等于设备返回错误码。
- 当前原记录266条全部保留追溯。同场景的参数值用实际步骤及逐编号预期在原条目表达；不为每个值机械拆行。同接口公共描述字段按连续相同内容合并，独立目的、步骤/预期/结果分别保留。当前保持原266条，不追加单独验证项。
- 拆分时原编号保留在原行；追加条目沿用该Sheet既有编号规则，从未使用的后续编号开始，不批量重编号。原条目与新增条目的对应关系记录在独立变更清单，不给业务表添加追溯列。最终条数按实际拆分统计，不承诺仍为266条。
- 有依据的前置、步骤和预期写成可观察描述；没有依据的字段写“待确认：具体问题及所需来源”。不得用“正常”“成功”“正确”替代判据。
- 每个会改变配置或运动状态的场景说明原值记录、恢复路径和恢复失败处理；仅设计这些步骤，不执行。

### 六个Sheet具体操作

1. **串口指令测试结果（原78条）**：按实际接口逐项完善版本、ID、波特率、使能、位置/速度、校零、状态、配置参数、IO及队列控制。将设置成功、读取一致、实际行为、断电保持分开判定。SDK参数范围注明当前库版本；非法原始帧的设备响应留待协议。`MoveGripperToAngle`、`SetModbus`缺入口的原场景保留待确认，不替换成其他方法。
2. **modbus指令功能测试（原78条）**：按同一组已认可测试点逐接口完善，但单独核对该通信路径的输入、返回、帧和异常依据。模式切换后的允许/禁止路径分别写明，避免把端口占用等环境问题当设备行为。当前4条空预期有依据则补齐，无依据则明确缺口。
3. **屏幕按键功能测试（原15条）**：按首页、配置页、position/current/speed、IO开关、波特率、四个动作按钮、校零、Modbus切换及信息页分组。显示与动作独立判定；电流单位、刷新、默认项和UI基线缺失时留待确认，不以SDK读数自动证明界面正确。
4. **modbus响应时间测试（原42条）**：保留每接口一行和统计字段，明确输入、前置状态、计时起止、超时/错误样本、统计口径及证据要求。SDK端到端与设备响应分开描述；样本数、预热和阈值无批准依据则待确认，旧表1000次不自动视为本轮批准次数。不填写实测值。
5. **串口指令响应时间（原42条）**：与Modbus独立填写上述测量口径，保留接口清单和环境字段。当前库40ms等待只说明实现，不能成为合格阈值或设备响应指标。缺入口的接口保留阻塞说明，不编造可测调用。
6. **力矩测试（原11条）**：保留1、10、20……100档，逐档写明被测物理量、装夹、传感器、单位、校准、采样、重复、恢复与判定依据。11条空预期改为有依据的判据或具体待确认项。优先级建议统一P1，作为本方案待批准内容；物理档位0未在已认可范围新增，不自行补入。档位不直接等同N或N·m，缺少独立依据不要求线性关系。

### 明确保留的资料缺口

独立v1.4.1协议/发布说明与构建信息；设备返回类型/编码、异常码、持久化与控制优先级；未找到的SDK入口；屏幕设计与单位；性能计时口径、样本要求及阈值；夹持力/扭矩定义、测量条件及合格区间。现有“无功能协议变化”仅为历史记录，不作为独立核实结果。

## P1：统一副本格式并检查

正文微软雅黑10号、常规字重、垂直居中、自动换行。编号/功能名称/接口/优先级水平居中；目的、前置、步骤、预期、实际、状态、回归、证据、备注按既有字段配方左对齐。响应时间表接口列居中，其余按配方左对齐。

正文用例网格黑色细线全边框，空白执行区域也保留边框；合并区域检查外围边框，不跨独立测试项合并结果。正文无背景填充；表头微软雅黑10号加粗、居中换行，保留基线表头边框及底色。首页保持原格式。83格历史混用字体在副本中按基线纠正，原件不改。详细依据为[单元格格式规则](../skills/testcase-iteration/references/cell-format.md)。

只在副本上开展工作簿结构和样式只读检查，逐Sheet应用既有模板映射。检查表头/合并/必填/编号/状态及字体/字号/对齐/边框，并核对公式、历史记录和首页未被意外改变。用例步骤及预期逐接口人工语义复核；打开或渲染检查长文本、行高、列宽和截断，未完成视觉检查必须单独说明。

现有原件19条预期空白、11条力矩优先级空白及27处待确认是初始检查基线。副本允许保留明确的资料缺口，因此检查结论必须区分“格式/结构合格”和“业务依据待确认”，不能为了检查全绿填猜测值。当前原执行栏为空，副本继续为空；如生成前发现新增历史结果则保留，并单独标识新条目尚未执行。
