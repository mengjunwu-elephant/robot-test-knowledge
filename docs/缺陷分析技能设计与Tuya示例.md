# 缺陷分析技能设计与Tuya示例

日期：2026-10-10。状态：设计稿，待用户评审；未新增可调用技能，未纳入v0.6.0。

## 已确认范围

用户选择缺陷分析、先设计并给示例、使用Tuya项目，并回复“确认执行”。本轮只读项目资料，形成技能设计及示例。不修改Tuya源码或业务用例，不运行pytest/collection，不建立SSH、ROS或设备连接，不提交缺陷到外部系统。

## 从什么问题出发

一次失败只证明某次观察与预期不一致。缺陷分析的作用是把实际现象、可信预期、证据和原因分开，帮助测试人员决定还缺什么、下一步验证什么。报错文本不等于根因；测试报告中的问题记录不等于本轮已复现。

## P0：先让分析可信

技能名称拟为defect-analysis。适用于用户明确要求分析失败日志、异常现象、缺陷记录或整理缺陷草稿；不由“写用例”自动触发。若用户只要整理缺陷，先完成可读草稿，不强求先做根因分析。

输入可是一句现象、日志、截图、测试报告或已有缺陷单。不要求所有字段齐全才开始：先提炼已有证据，再集中问影响结论的缺口。优先获取项目/模块、发生版本、实际行为、正确行为依据、发生条件/步骤、日志与时间、影响范围及复现次数。报告只给次数而不给总样本时，不计算失败率。没有真实接口名就按功能描述，不能编造API。

输出按以下顺序：一句话问题摘要；实际与预期；证据及来源；当前判定；原因假设及反证；建议补充的最小验证；可复制缺陷草稿；缺口与关闭条件。信息简单时合并段落，不为填模板制造内容。

判定必须区分：已确认产品缺陷、缺陷候选待确认、测试脚本/数据问题、环境问题、已知使用边界、暂无法判断。没有需求或协议依据时，不把观察异常直接定为产品缺陷。证据冲突保留双方来源，提示用户选择流程依据；技能包流程优先不能覆盖真实接口契约。

严重程度描述对业务的实际影响；优先级描述修复先后。先读取项目现有定义，未定义时只给建议及理由，不虚构团队等级、不自动派责任人。根因只有能关联版本、条件和关键证据，并排除主要替代解释时才标“已证实”；其余写“假设/待验证”。

## P1：让测试人员拿来就能用

对话示例：“分析Tuya红外回充报告中的2米检测不稳定问题，先整理缺陷草稿，原因没有证据就标待验证，不运行测试。”

拟定流程：读取项目规则与相关资料→提炼现象/依据/证据→判断现有证据能支持到哪一级→列少量可区分原因的验证→形成缺陷草稿。不要把故障注入、运动、断电或重新测试当作默认动作。实际补测另需明确授权；建议与已执行记录分开。

拟定技能资源：skills/defect-analysis/SKILL.md保持入口、流程、事实与假设边界；references/evidence-and-classification.md维护证据及判定原则；references/tuya-example.md放去敏真实案例；assets/defect-draft.md提供可复制字段。确有重复需求才加脚本。本轮仅设计这些路径，不创建占位技能。实现时同步.agents/skills及现有打包、安装、离线检查的两技能清单，不能只新增目录就宣称可安装。

### 资料与证据级别

本轮读取的是既有报告方案中的汇总结论，未逐一验证原始图片或终端日志。以下属于有来源的历史记录分析，不是本轮复现结论。报告记录：1米正对正常检测；2米正对可检测但不稳定；1米内正对无遮挡条件下对接10次均进入充电状态。报告同时记录侧对/遮挡无法检测为使用边界。没有信号强度、采样频率、算法阈值或2米重复试验总次数。

### 一句话摘要与判定

“2米正对充电桩时，红外信号可被检测，但检测稳定性不足。”

当前判定：缺陷候选，待确认2米稳定检测的产品要求；也可能属于已知距离边界。不能仅凭现象认定软件算法缺陷。1米内10次对接成功仅支持报告所述条件和样本，不能推导2米对接稳定或总体成功率。

### 原因假设与区分方法（尚未执行）

假设1：距离增大导致接收信号裕量不足。待取得同条件不同距离的原始信号与检测状态，观察两者是否关联；当前没有信号强度数据。

假设2：光照、安装角度或路径条件变化影响接收。待在可记录且保持一致的条件下比较数据；不要把“正对”当成精确角度已测量。

假设3：检测阈值、滤波或状态切换逻辑造成抖动。待核对对应版本实现和时间序列；未知参数不填数值，不先给“调阈值”的修复结论。

建议最小资料补齐顺序：先确认产品要求及测试版本→获取原始证据、检测状态定义及2米样本次数→再设计能区分上述假设的补测。条件、次数和判定阈值由实际标准确认，本设计不预设100次或成功率门限。

## P2：评审通过后才实施

验收重点：测试人员能从摘要看懂问题；事实和假设分开；每条结论有来源；缺失数据不猜填；验证建议能区分原因；不跨任务触发测试或写外部系统。

后续行为验证至少覆盖四类输入：资料充分的失败记录、只有一张截图、预期与实现冲突、历史修复记录但缺少回归证据。应观察技能是否正确保留不确定性，不用匹配固定措辞的测试冒充行为验收。

本设计评审通过后，再实现技能、镜像和第三技能打包适配，并单独完成试用和新版发布。当前正式v0.6.0仍只有两项技能。
