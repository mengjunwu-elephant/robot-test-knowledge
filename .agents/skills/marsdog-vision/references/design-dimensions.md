## 3. 维度清单（编写时勾选）

### 3.1 正常

- 目标入画或姿态/表情成立 → 满足稳定条件后**上报一次**（已确认名或「待确认」）。  
- 调试页身份/跟踪与事件一致（有依据的字段才硬断言）。

### 3.2 边界

- **T_enter**：闪现不足不上报；刚超过可上报（容差未定义则记录实测，不猜 ±）。  
- **置信度**：低于任务阈值不上报；无专条时标**待补**，勿假装 F 区分布记录已覆盖。  
- 距离/角度/遮挡：仅在有需求或已确认测试点时展开。

### 3.3 状态机（ENTER / HOLD / EXIT / TRIGGER）

| 状态/迁移 | 用例要点 |
| --- | --- |
| ENTER | 稳定 ≥T_enter 成立时刻上报；仅 1 条 |
| HOLD | 持续在画：**Topic 无新增同类事件** + **不重复直驱**；HOLD 为内部状态时不要求消息体含 state |
| EXIT | 丢失 ≥T_exit；**开发已确认不发结束通知**时写「不再出现 / 不发结束通知」，不臆造 EXIT 报文 |
| TRIGGER | 瞬时成立 1 条；持续期间不重复；解除后可再触发 |

状态机日志当前不可观测时：判据退化为 Topic/行为/调试页；备注「日志落地后补验」。

### 3.4 重触发

- 未满 **T_retrigger** 再满足 T_enter → 不重新 ENTER。  
- 超过间隔后再稳定 → 可再 1 条并允许再直驱一次。  
- 步骤写明「稳定保持 ≥T_enter」，避免与门控混淆。

### 3.5 情绪（可测 vs 待确认）

- 硬测：按 1023/L2 写增量与表现。  
- 观测未定：标待确认，不假装「一律挂起」，也不无条件勾选通过。  
- 禁止「情绪无变化」；改写「无因该事件产生的映射增量」。

### 3.6 双分支（陌生人）

- 1023 常见 **同条内**两分支硬断言；也可拆行以利执行——以当次方案为准。  
- 分支名已开发确认则可写预期；否则「待确认」。  
- 未确认分支条件前，不得只验上报却勾选情绪分支通过。

### 3.7 异常与恢复

- 身份误判不错误上报；缺专条时标待补。  
- 多人入画：按表内/已批准范围；未批准不扩。  
- 节点重启、崩溃拉起：1023 常缺专条 → **待补**，不拿「异常容错」冒充。

### 3.8 性能与长稳（F / G）

与功能同表分区：准确率、时延、长稳、泄漏、资源、容错、频率等。

- 阈值未拍板 →「待确认」或「记录实测，待基线」。  
- 玩具准确率等缺口 → 待补。  
- 禁止把无依据的 ≥90%、≤500ms、24h 等写成既定验收线（除非产品/L3 书面给出；表内已写时长须标明来源）。

### 3.9 优先级仲裁

仅书面批准纳入时展开：安全 > 主人身份 > 主人情绪 > 互动姿态 > 物品。样本可作写法参考，**不**自动升格为默认 P0。

## 4. 落行规则

| 规则 | 说明 |
| --- | --- |
| 编号 | 默认 `MD-VDE-*` + 模块字母分区 |
| 1 点 ≥ 1 行 | 可捆行（1023）；拆行须在方案说明，非强制情绪挂起 |
| 优先级 | 经典主路径优先；表内 P0 ≠ 自动全部默认生成 |
| 测试目的 | 「验证…」对准本行预期 |
| 扩展 | **无书面批准范围 → 不生成阻塞行** |
