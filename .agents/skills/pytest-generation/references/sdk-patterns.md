# SDK场景参考

用于直接调用项目SDK的查询、普通设置及异常测试。读取[data-and-evidence.md](data-and-evidence.md)后核对当地fixture与邻近源码；不导入SDK验证，不创建连接，不复制Tuya固定返回码、异常名、上电逻辑和运动值。

## 查询示例（步骤说明，非可执行模板）

取已确认参数和真实预期→通过现有fixture调用查询→记录原始返回→按项目契约解包→断言类型/结构→比较业务数据→附预期/实际证据。版本返回不能从一个项目的float断言推广到其他SDK。

## 普通设置示例

查询并验证原值→保存涉及对象的各自状态→在try中用已确认输入设置→分别验证设置业务返回与getter回读→finally按责任恢复并再次getter验证→恢复完成后才记通过。回读预期与setter返回预期分开，不把expect_data同时当两者。

Tuya的device.result_data是当地统一业务提取方法的实例，不是通用方法名；读取目标已有实现，禁止每个测试重复做CommandResult分支。双臂模式可能有联动异步状态，提炼的是“恢复所有受影响状态”，不复制具体联动或默认值。

## 异常示例

先核对具体异常及是否属于SDK本地校验→通过现有fixture调用已批准非法参数→pytest.raises捕获具体异常→块外记录错误证据。不得用Exception包住所有问题；协议拒绝响应与Python异常分层，不混作同一预期。

## 禁止继承的局部问题

抽样SDKdebug设置案例有英文Allure标题，finally只写回未回读；源项目规则要求中文及恢复证据。提炼时按确认规则完善输出，保留原项目不改；不能把邻近文件当绝对正确模板。

运动、回零、校准、掉电、升级不提供执行模板。原项目门控、姿态及专项授权保持，普通setter也不能因为“设置”两个字默认安全执行。
