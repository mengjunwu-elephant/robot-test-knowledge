# ROS 用例
模板：assets/templates/ROS测试用例模板_v1.0.xlsx。
环境配置与 Service、Topic、Action（按需启用）分开；接口专用字段为所属模块、ROS 接口名称、消息／服务／动作类型，保留位置。
先确认发行版、Launch、消息/服务/动作定义、版本和 QoS，不从旧项目复制端点、请求字段、时序或预期版本号。
Service：请求、响应结构与值、失败、状态回读和恢复。Topic：首帧、内容、采样窗口、频率/抖动、反馈关联；无关联 ID 不算单帧响应时间。Action：目标、反馈、最终结果、取消和超时。
发布成功只证明发送/发布，不证明设备动作完成；动作需安全前置、观察证据和恢复责任。写零位标定与运动回零不能混为一个行为。不执行 SSH、ROS 或设备连接。
人工模板编号不能改成 automation_id；如转自动化，另核对当前项目加载器字段映射。
模板保留原字段、顺序、两层环境表头与样式；每个环境记录实际结果、执行状态、回归测试记录、测试证据。正式用例无背景填充；有内容的用例区使用细实线全框线（含空结果栏）。描述字段仅同组相邻且内容相同时合并，独立测试项的步骤、预期与结果不跨项合并。无前置填“/”。
优先级：P0 阻断后续测试或严重安全/不可恢复数据损失；P1 核心/高风险；P2 常规/常见异常/边界；P3 低风险辅助。优先级不是缺陷严重程度。
状态仅 Pass、Fail、Blocked、Not Executed、N/A；后两种实际结果留空，失败/阻塞/关键测量附证据。步骤、预期、实际结果按序号对应。实际环境名称须与首页一致。
