# 团队公共测试规则（0.5.0）

用例编写与自动化编写/自检分开授权。仅要求编写、完善或评审用例时，不开展pytest源码审查、数据映射检查、AST自检、collection或执行；可阅读必要SDK源码核实接口事实。历史试用意向不代表当前自动化授权。明确要求自动化后，区分生成、静态检查、collection和执行范围，静态检查授权不等于运行授权。
测试点评审以接口名称及对应接口测试点为核心，按Sheet/协议路径分组，默认使用“接口名称｜对应测试点｜待确认依据”表格；同一接口的独立测试点分行或在单元格内逐项换行。非接口场景用功能/测量项目代替接口名。主评审表不显示评审编号、原ID/行号或其他管理字段；原ID及行号仅保留在追溯附件。未知入口明确标注，不编造接口；评审视图不改变原Excel字段。

编写或迭代用例必须先确认实际Sheet范围，再单独输出测试点并确认，之后输出完整方案、同步方案总文档并取得针对方案的“确认执行”，再生成副本。已明确批准的相同范围不重复确认，技能升级批准不能替代具体项目范围批准。
格式基线须明确字体字号、全边框和字段对齐；夹爪v1.4.1基线正文微软雅黑10号、垂直居中、自动换行，编号/功能名称/接口/优先级居中，其他字段按配方左对齐。表头和首页区别处理，异常混用字体不沿用。共享规则不能静默修改原项目文件。
先检索项目现有 AGENTS.md、规则和技能；先看资料与源码，再设计测试。
明确用户指令与平台约束优先。在团队测试规范范围，公共规则优先，项目独立规则补充差异。发现冲突记录来源、采用规则和影响，不静默修改项目规则。
公共规范不能代替 SDK 事实：型号、版本、返回值、异常与限位必须来自当前可信资料；不同项目契约不能混用。
保留 Excel 字段/顺序/Sheet/ID/公式/样式，以及 pytest Fixtures、Allure、marker、skip、单接口结构和恢复流程；修改先出差异副本。
不连接或控制实体机器人，不执行设备测试或有连接副作用的 collection。
新方案至少询问三个收敛问题，收到“确认执行”后输出并实施；既有授权范围不重复确认。
方案按 P0/P1/P2 更新项目方案总文档；任务完成更新项目唯一交接文档以及相关规则技能。
记录实际使用的技能版本与证据缺口。其他团队成员通过 PR 修改，维护者审核后发布；@mengjunwu-elephant 本人提交或明确授权代提交免人工审批，校验通过后可直接合并发布；使用最新正式 Release，草稿/预发布不进入团队使用。

用例编写资料冲突默认以技能包规范为准；提示具体来源、差异与影响，让使用者确认采用哪一份。明确选择后记录并执行，接口契约不明仍待确认。允许共享用户授权项目资料，排除密钥、访问参数和现场连接配置；优先提炼规则与示例。

用例前置只写必要状态，不重复环境结果列；每步实际调用/人工动作与预期逐编号对应。同接口公共描述字段按相同内容连续合并，不机械追加单独验证行。响应时间名称/API列不写流程或资料说明。
