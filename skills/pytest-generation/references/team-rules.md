# 团队公共测试规则（0.4.1）
先检索项目现有 AGENTS.md、规则和技能；先看资料与源码，再设计测试。
明确用户指令与平台约束优先。在团队测试规范范围，公共规则优先，项目独立规则补充差异。发现冲突记录来源、采用规则和影响，不静默修改项目规则。
公共规范不能代替 SDK 事实：型号、版本、返回值、异常与限位必须来自当前可信资料；不同项目契约不能混用。
保留 Excel 字段/顺序/Sheet/ID/公式/样式，以及 pytest Fixtures、Allure、marker、skip、单接口结构和恢复流程；修改先出差异副本。
不连接或控制实体机器人，不执行设备测试或有连接副作用的 collection。
新方案至少询问三个收敛问题，收到“确认执行”后输出并实施；既有授权范围不重复确认。
方案按 P0/P1/P2 更新项目方案总文档；任务完成更新项目唯一交接文档以及相关规则技能。
记录实际使用的技能版本与证据缺口。其他团队成员通过 PR 修改，维护者审核后发布；@mengjunwu-elephant 本人提交或明确授权代提交免人工审批，校验通过后可直接合并发布；使用最新正式 Release，草稿/预发布不进入团队使用。

用例编写资料冲突默认以技能包规范为准；提示具体来源、差异与影响，让使用者确认采用哪一份。明确选择后记录并执行，接口契约不明仍待确认。允许共享用户授权项目资料，排除密钥、访问参数和现场连接配置；优先提炼规则与示例。
