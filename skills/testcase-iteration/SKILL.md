# 用例编写与迭代

先读取 [团队公共规则](references/team-rules.md)。技能版本 0.4.1。离线时报告当前版本，不声称已是最新版；安装目录 Update.cmd 可更新正式版，刷新插件并开启新对话后使用。

## 输入与确认
检索项目已有 AGENTS.md、规则、技能、方案及唯一交接；读取已有用例、可信接口资料、软件/固件/SDK 完整版本和相关源码。用 [项目差异参考](references/project-context.md) 识别差异，重新验证快照。
先确定被测行为、独立预期依据、可观察结果、环境和恢复责任，不能从当前实现反推正确答案。
新任务漏斗式至少确认三个问题：新旧版本及新增/修改/删除（无变更也记录）、适用模板/Sheet 与调整范围、预期依据和交付边界；收到“确认执行”后再输出并实施方案。既有授权范围不重复确认。

## 选择写法
- 新通用软件用例读取 [通用软件写法](references/general-software.md)。
- 固件、协议或 Python 库用例读取 [固件写法](references/firmware.md)。
- ROS Service、Topic、Action 用例读取 [ROS 写法](references/ros.md)。
- 资料冲突读取 [冲突处理](references/conflicts.md)，给出默认使用技能包规范及用户选择入口。接口事实不明确时保留待确认。
- 新表从 assets/templates 的适用模板复制；旧表保留原字段和结构，必要变更先取得明确选择，不直接套新表。详见 [字段与检查](references/workbook-review.md)。

## 设计与交付
按已确认行为选择正常、边界、异常、状态转换、超时、恢复与回归场景，不凑用例数量。每个可独立判定的测试项单独写目的、具体步骤和可判定预期；参数、单位、限位、返回和异常均需证据，缺项标为待确认。
制作逐行变更清单，保留旧 Sheet/行号/ID、公式、样式、历史失败和回归。先产出副本；不同环境分别记录，未执行不填实际结果或 Pass，旧版本结果不得迁入新版本。
来源、冲突选择和版本记录在项目既有记录或独立变更说明，不擅自增加 Excel 列。SDK title 和 ROS automation_id 不混用；写用例不重构 Fixtures、Allure、单接口代码或恢复逻辑。
用 scripts/review_workbook.py 做只读检查，列出自动发现问题与人工未验证项；工具不代替语义评审、视觉检查或设备验证。按 [三类示例](references/examples.md) 核对输出，而不是复制其中演示预期到真实项目。
方案按 P0/P1/P2 更新方案总文档，任务完成更新唯一交接及相关规则技能。输出文件/Sheet/改动、依据、冲突与待确认、离线验证。不得连接设备或执行硬件测试。
