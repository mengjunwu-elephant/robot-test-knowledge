# PIT-006 迁移目的、方案对照与来源空项

适用：把旧用例迁入当前模板，或审查已经有确认方案的工作簿。

- 旧表「测试类型/方法/维度」不写入测试目的或备注。测试目的按该行预期写成「验证…」。步骤、预期和优先级按已确认原文保留。预期为空或对不上时，测试目的写待确认。用户当次明确要求测试目的按原文时，遵守该句。
- 内容审查对照已确认方案或交接范围，只报告差异，不因审查改写工作簿。没有方案时按需求、协议和旧表核对。
- 来源单元格本来为空的优先级、步骤或编号，交付里单独标「来源既有缺口、不补」。来源有值而副本丢失，仍算生成缺陷。这些空项单独列出，不把整本说成生成失败。

依据：2026-10-20 至 2026-10-21 的 ultraArm 用例迁移与审查对话。主控表曾把测试方法写入测试目的，用户指出后改为「验证…」。屏幕 v1.2.9 审查报告了与已确认范围不一致的计时、循环和掉电内容，审查本身未改原件。主控副本和全量表的结构结果把来源本来就空的优先级、步骤报成结构未通过。2026-10-23 用户确认上述三条写法。原工作簿未在本仓库独立复核。此记录说明迁移和报告方式，不证明那些副本仍有缺陷，也不把 ultraArm 的字段分组推广到其他项目。

不适用：用户当次要求测试目的、步骤或空项按另一套原文处理。本短参考尚未进入正式包。
