# 正式规范用例条款摘录
来源：软件测试标准流程规范文档v2.1.0.docx，第4章；2026-10-09静态提取。仅保留用例相关条款，不复制含访问参数的链接。

4.1.1  测试用例文件按产品或项目、软件名称和完整版本号命名。每个正式版本只维护一个有效用例文件，版本内修改依靠平台历史版本，不创建“最终版2”等重复文件。

4.2.1  用例文件应说明本版本新增、修改、删除内容、测试范围及实际环境基线。内容不明确时，测试人员应先完成需求澄清。

4.3.1  编号、功能名称、测试目的、优先级、测试步骤、预期结果及适用的专用字段为必填。测试目的以一句话说明验证场景和目标；无前置条件填写“/”，备注选填。不单设用例标题、测试方法、接口描述、测试数据或关联缺陷列。

4.3.2  用例优先级使用P0—P3。P0为应最先验证的阻断后续测试或涉及严重安全、不可恢复数据损失风险的场景；P1为核心流程及高风险场景；P2为常规功能、常见异常和边界场景；P3为低风险辅助功能。优先级用于执行顺序及回归选择，不单独决定是否跳过测试，也不等同于缺陷严重程度。

4.3.3  同组相邻且内容相同的编号、功能名称、测试目的、前置条件等描述字段可以合并。每个可独立判定的测试项分别记录执行结果，不跨项合并结果单元格；数量按独立判定项计算，不按合并后的编号数量计算。各环境分别统计，跨环境合计标明为执行项数。

4.3.4  模板首页以禅道测试单和开发提测资料为信息来源，登记禅道测试单编号、需求／任务名称、提测人／提测时间、被测对象、完整版本号／构建信息、测试包位置、版本变更摘要、验收依据／需求链接、测试范围／排除项、风险／限制、设备与依赖版本及测试环境。ROS补充发行版与运行配置。各环境名称由项目确定，并与首页环境登记一致。

4.4.1  正式用例的填写区域使用无背景填充，避免颜色被误解为执行状态或优先级。新增、修改、删除等背景色只用于填写说明与示例页：绿色表示新增，黄色表示修改，灰色表示删除；沿用内容不填充。

4.5.1  每个环境均记录实际结果、执行状态、回归测试记录和测试证据。执行状态使用Pass、Fail、Blocked、Not Executed、N/A；失败、阻塞和关键测量项必须附证据。

4.5.2  多步骤用例的测试步骤、预期结果和实际结果按1、2、3逐项对应。实际结果记录观察到的现象或数值；Not Executed和N/A的实际结果留空。

4.5.3  回归记录按日期追加失败原因、复测结果和必要说明；当前状态只反映最近一次执行，历史失败记录不得删除。
